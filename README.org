#+title: Jelly and *arr stack on a Gentoo server

This document describes my current setup for running a Jellyfin media library server with an *arr stack setup, HTTPS connection on a PC operating as a server with Gentoo as the OS operating as a virtualization platform.

It is composed of 3 main parts:
1. The Gentoo machine that acts as the platform from which to run the docker services
2. The docker-compose file that keeps the configurations for Jellyfin and the *arr stack
3. Caddy as a reverse proxy to access the media library with secure HTTPS
* Gentoo

Firstly, I'm running this setup on an HP Compaq office computer with an upgraded Intel Q9650 processor and 8GB DDR3 RAM. Obviously not much compared to today's computing standards, but this is why I chose Gentoo to run these services. Gentoo is very lightweight, and has a lot of optimizations that can make more modern software run on much older systems. Turns out, you really don't need the latest compute for every task.

I have everything compiled with the hardened profile to add some extra protection. This profile adds things like compile-time buffer checks and stack smashing protection. It is not the same thing as SELinux, though that profile is also available as an option.

** My make.conf:

#+begin_src unix-conf

COMMON_FLAGS="-march=core2 -Os -pipe"
CFLAGS="${COMMON_FLAGS}"
CXXFLAGS="${COMMON_FLAGS}"
FCFLAGS="${COMMON_FLAGS}"
FFLAGS="${COMMON_FLAGS}"
RUSTFLAGS="-C target-cpu=penryn"
LDFLAGS="-Wl,--as-needed -Wl,--sort-common -Wl,--gc-sections -Wl,--hash-style=gnu"

MAKEOPTS="-j4 -l5"
CPU_FLAGS_X86="mmx mmxext sse sse2 sse3 ssse3"
USE="-systemd -bluetooth -wifi -X -gtk -qt5 -qt6 -vulkan -alsa -pulseaudio -pipewire -wayland -opengl -cups -vlc -vaapi -qsv docker nfs samba dist-kernel"
PORTAGE_SCHEDULING_POLICY="idle"

LC_MESSAGES=C.UTF-8

GENTOO_MIRRORS="https://mirror.leaseweb.com/gentoo/"
ACCEPT_LICENSE="*"
ACCEPT_KEYWORDS="~amd64"

#+end_src

A couple things to note about this:
- My -march flag is set to the actual architecture name of the CPU I have in the machine. This is because using "-march=native" will force the compiler to spend some compute figure out what archiecture to compile for.
- The "-0s" flage provides everything that "-02" does while optimizing for size of output files.
- There are a few linker flags passed to GCC. "--as-needed" reduces unnecessary dependecies by only linking libraries actually used by the compile target. "--sort-common" sorts symbols by alignment. "--gc-sections" tells the GNU linker to to garbage collection. "--hash-style=gnu" tells the linker to use the generate a .gnu.hash section instead of the older .hash. These are all put here to generally speed up startup and operation.
- The many USE flags are getting rid of any video/audio output because this is a headless system, systemd because we're using OpenRC as the init, and some CPU features that the older Q9650 processor I'm using doesn't possess
- [[https://wiki.gentoo.org/wiki/Portage/niceness][Portage scheduling policy]] gives the emerge command a low priority compared to other scheduled processes, helping services stay up when running emerge commands.
- The "~amd64" in ACCEPT_KEYWORDS essentially brings the system up to a rolling-release style system.

* Caddy

Now, in the Caddy project folder, there's the compose.yml for Caddy, which listens on ports 443 to reverse proxy into the docker services specified in the *arr stack compose file. First, I created the docker network by running as user =docker network create caddy= . Once the docker-compose.yml file was created as below, I ran =docker compose up -d= and did the same in the Jellyfin server folder.

The domain I used was purchased through Namecheap and since my ISP uses dynamic public IP addressing, I created DyDNS records for the subdomains and used ddclient on the server as a daemon to automatically update the public IP. This all allows the services to communicate with each other securely via HTTPS, and lets me access the webUI portals the same way from a browser.

#+begin_src dockerfile :tangle ./caddy/docker-compose.yml :mkdirp yes

services:
  caddy:
    image: lucaslorentz/caddy-docker-proxy:ci-alpine
    container_name: caddy
    ports:
      - 80:80
      - 443:443/tcp
      - 443:443/udp
    environment:
      - CADDY_INGRESS_NETWORKS=caddy
    networks:
      - caddy
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - caddy_data:/data
    restart: unless-stopped

networks:
  caddy:
    external: true

volumes:
  caddy_data: {}
  
#+end_src

* Binding qBittorrent to a VPN

Normally, when a consumer VPN like Mullvad or ProtonVPN is active on a host machine, it will block it off from communicating to any other device on the local network. This is just how VPNs work by way of putting all traffic through an encrypted tunnel. What we need is something that can bind only the qBittorrent service through a VPN, and not anything else on the machine. Luckily, such a project does exist: [[https://github.com/passteque/gluetun][Gluetun]]

** qBittorrent + Gluetun

#+begin_src dockerfile :tangle ./media-stack/docker-compose.yml :mkdirp yes

  services:

    gluetun:
      image: qmcgaw/gluetun:latest
      container_name: gluetun
      cap_add:
        - NET_ADMIN
      devices:
        - /dev/net/tun:/dev/net/tun
      ports:
        - 8080:8080
        - 6881:6881
        - 6881:6881/udp
      environment:
        - VPN_SERVICE_PROVIDER=${VPN_SERVICE_PROVIDER}
        - VPN_TYPE=${VPN_TYPE}
        - WIREGUARD_PRIVATE_KEY=${WIREGUARD_PRIVATE_KEY}
      networks:
        - caddy
      labels:
        caddy: qbittorrent.${FQDN}
        caddy.reverse_proxy: "{{upstreams 8080}}"
      restart: unless-stopped
    
    qbittorrent:
      image: lscr.io/linuxserver/qbittorrent:latest
      container_name: qbittorrent
      environment:
        - PUID=${PUID}
        - PGID=${PGID}
        - TZ=${TZ}
        - WEBUI_PORT=8080
      volumes:
        - ./qbittorrent:/config
        - ${DOWNLOADS_PATH}:/downloads
      restart: unless-stopped
      network_mode: "container:gluetun"
      depends_on:
        gluetun:
          condition: service_healthy
#+end_src

* Jellyfin + Arr Stack

Now, for the main compose file where Jellyfin and the Arr stack is configured. On my machine I have an environment file that holds the variable options which is what you see in, for example ${TZ} for my timezone.

I use a 4TB hard drive mounted to /opt/mediaserver/tbdrive that hold the active downloads and completed media files after Sonarr and Radarr reorganizes them for Jellyfin.

qBittorrent is the download client whose ports are attached to Gluetun, which holds the Wireguard VPN configuration generated from ProtonVPN.

Every other container is in the caddy network, which I'll go over in the next section. Instead of directly publishing ports in the config, the caddy.reverse_proxy label specifies the ports for Caddy to reverse proxy so they can be accessed via HTTPS in port 443.

The only service not in either the Caddy reverse proxy or routed through Gluetun is the Flaresolverr service, which I've found only really works correctly without them. This service will solve Cloudflare captchas automatically and is necessary for the *arr services to query torrent sites.
